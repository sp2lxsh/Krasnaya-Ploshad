# redsquare-mebel.ru — правки

Работы без доступа к хостингу, только через админку WordPress.

**Как поставить плагины из `mu-plugins/` без FTP:** запаковать каждый `.php` в отдельный zip
и загрузить через *Плагины → Добавить новый → Загрузить плагин*, затем активировать.
Если доступ к файлам есть, можно просто положить файлы в `wp-content/mu-plugins/`: так их нельзя случайно отключить.

## 0. Что ещё запросить у заказчика

1. **WooCommerce → Статус → Статус системы → «Получить системный отчёт».** В конце отчёта раздел *Templates*:
   какие шаблоны WooCommerce переопределены в теме `red-square` и какие из них устарели.
2. Подтвердить хостинг и то, что в панели хостинга есть резервные копии за последние дни. Если это Beget —
   *Панель → Резервное копирование*. Это готовый откат «на всякий случай», даже если сами мы в панель не заходим.
3. Доступ к почте, указанной в **Настройки → Общие → Адрес e-mail администрации**. Если после обновления
   сайт упадёт с фатальной ошибкой, WordPress пришлёт туда ссылку на «режим восстановления».

## 1. Бэкап без хостинга

На сайте уже стоит **Duplicator** — он собирает архив прямо из админки.

1. Сначала *Duplicator → Пакеты*: посмотреть, нет ли там старых пакетов, — возможно, они и занимают
   эти 1,5 ГБ. Скачать нужные, остальные удалить.
2. *Пакеты → Создать*. На вкладке *Archive → Files* включить фильтр папок и исключить
   `wp-content/uploads` (20,9 ГБ — с ним пакет не соберётся), `wp-content/cache` и `wp-content/backups-dup-lite`.
   Базу данных оставить. Получится ~300–400 МБ.
3. Собрать пакет, скачать `archive.zip` и `installer.php` к себе.
4. Если пакет не собирается — отметить *Archive only the database*: база важнее всего.
5. После работ удалить пакеты в Duplicator: архивы, которые можно скачать с сервера, — это уязвимость.

## 2. Порядок обновления

Обновлять по одному плагину и после каждого открывать главную, каталог, карточку товара, корзину, оформление заказа и админку.
Сначала плагины, **ядро — последним**: свежие версии плагинов рассчитаны на WP 7.x, старые — нет.

| Шаг | Что | Комментарий |
|---|---|---|
| 1 | Удалить *WordPress Importer* (неактивен), выключить *Show Current Template* | Утилиты разработчика, на рабочем сайте не нужны |
| 2 | Better Search Replace, WP Mail SMTP, Contact Form 7, 301 Redirects, VK Ads Pixel | Минорные, риск низкий. После CF7 отправить тестовую заявку, после WP Mail SMTP — тестовое письмо. Better Search Replace потом можно деактивировать |
| 3 | WP Fastest Cache | После обновления очистить кеш |
| 4 | ACF PRO 6.3.4 → актуальная | Лицензия активна; если обновление не видно — *Консоль → Обновления → «Проверить снова»*. Поля хранятся в JSON в теме, обновление их не трогает |
| 5 | Yoast SEO 26.5 → 28.5 | Может запустить фоновую переиндексацию; на 3500 товарах делать в спокойное время |
| 6 | Cyr-To-Lat 6.6 → 7.1 | Мажорная версия. **Не запускать** конвертацию существующих ярлыков — сменятся URL |
| 7 | Duplicator 1.5 → 5.x | После того, как сделан бэкап |
| 8 | WooCommerce 10.3.8 → актуальная | Только если в статусе системы нет устаревших шаблонов, иначе сначала обновить их в теме. После обновления может понадобиться обновление БД WooCommerce — запустить его |
| 9 | Twenty Twenty-Five 1.0 → 1.5 | Не удалять: это запасная тема, на которую WordPress переключится, если основная сломается |
| 10 | Ядро WordPress 6.9.9 → 7.1.2 | Последним. Только при наличии бэкапа и когда заказчик может в любой момент откатиться через хостинг |

Если плагин с wordpress.org сломал сайт после обновления, его можно откатить плагином **WP Rollback**. Для ACF PRO нужно заранее сохранить zip текущей версии.

## 3. Салон удалён → товары тоже (`mu-plugins/rs-salon-products.php`)

- Салон в корзину → его товары в корзину. Салон восстановлен → вернулись только эти товары, с прежним статусом.
  Корзина очищена → товары удаляются навсегда (вместе с вариациями, картинки в медиатеке остаются).
- Товар, привязанный ещё к другому салону, не трогается.
- Если товаров больше 50, работа идёт в фоне через Action Scheduler: *WooCommerce → Статус → Запланированные действия*, группа `rs-salon-products`.

Тип записи «Салоны» и поле ACF у товара, где выбран салон, определяются **автоматически**.
После установки откройте список салонов:

- вверху будет уведомление вида «Тип записи: `…`, поле товара: `…`»;
- в таблице появится колонка **«Товаров»**. Если там реальные цифры, всё найдено правильно.

Если там жёлтое предупреждение или нули, плагин ничего удалять не будет. Тогда надо задать `RS_SALON_POST_TYPE` / `RS_SALON_META_KEY`
вручную (`define(...)` в `wp-config.php` или в начале файла плагина). Имя поля — *ACF → Группы полей →* группа товара → колонка «Имя».

Первую проверку делать на салоне-черновике или сразу восстанавливать салон из корзины.

## 4. Спам (`mu-plugins/rs-antispam.php` + настройки)

Плагин:
- комментарии открыты только у товаров (отзывы), у остальных типов записей закрыты; пингбеки и трекбеки отключены;
- в форму добавлены скрытая ловушка и подписанная метка времени. Боты, которые отправляют POST сразу в `wp-comments-post.php`,
  и слишком быстрые отправки отсекаются;
- отзывы со ссылками или без кириллицы попадают в «Спам»;
- спам старше 14 дней удаляется автоматически.

После установки оставить тестовый отзыв без авторизации. Если он дошёл до «Ожидают проверки», можно поставить `RS_ANTISPAM_STRICT = true`:
тогда запросы без токена даже не записываются в базу.

Настройки (**Настройки → Обсуждение**):
- снять «Разрешить оповещения с других блогов»;
- снять «Разрешить комментарии к новым записям» (сейчас включено). На отзывы к товарам это не влияет;
- включить «Комментарий должен быть одобрен вручную».

**WooCommerce → Настройки → Товары:** «Отзывы могут оставлять только подтверждённые покупатели» — радикальный,
но самый надёжный вариант, если отзывы к товарам не нужны от всех подряд.

Накопившийся спам удалить через *Комментарии → Спам → «Очистить спам»*.
