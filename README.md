# redsquare-mebel.ru — правки

Работы без доступа к хостингу, только через админку WordPress.

**Как поставить плагины из `mu-plugins/` без FTP:** запаковать каждый `.php` в отдельный zip
и загрузить через *Плагины → Добавить новый → Загрузить плагин*, затем активировать.
Если доступ к файлам есть, можно просто положить файлы в `wp-content/mu-plugins/`: так их нельзя случайно отключить.

## 0. Что запросить у заказчика

1. **Инструменты → Здоровье сайта → Информация → «Скопировать информацию о сайте в буфер обмена».**
   Там есть почти всё нужное: версии WP, PHP, MySQL, тема, `memory_limit`, `max_execution_time`, размеры папок и БД.
2. **WooCommerce → Статус → Статус системы → «Получить системный отчёт».** В конце отчёта раздел *Templates*:
   какие шаблоны WooCommerce переопределены в теме и какие из них устарели.
3. Доступ к почте, указанной в **Настройки → Общие → Адрес e-mail администрации**. Если после обновления
   сайт упадёт с фатальной ошибкой, WordPress пришлёт туда ссылку на «режим восстановления».
4. Доступ к хостингу/FTP хотя бы «на всякий случай». Без него обновление ядра нельзя откатить, если сайт не откроется.

## 1. Бэкап без хостинга

На сайте уже стоит **Duplicator** — он собирает архив прямо из админки.

1. Duplicator → Пакеты → Создать. На вкладке *Archive → Files* включить фильтр папок и исключить
   `wp-content/uploads` и `wp-content/cache` (картинки при обновлениях не меняются, а архив без них в разы меньше).
   Базу данных оставить.
2. Собрать пакет, скачать `archive.zip` и `installer.php` к себе.
3. Если пакет не собирается из-за таймаута — на той же вкладке отметить *Archive only the database*: база важнее всего.
4. Лучшее, что можно сделать за ~30 минут: развернуть этот пакет локально (LocalWP/OpenServer) и сначала обновить там.
5. После работ удалить пакеты в Duplicator: скачиваемые архивы на сервере — это уязвимость.

## 2. Порядок обновления

Обновлять по одному плагину и после каждого открывать главную, каталог, карточку товара, корзину, оформление заказа и админку.

| Шаг | Что | Комментарий |
|---|---|---|
| 1 | Удалить *WordPress Importer* (неактивен), выключить *Show Current Template* | Утилиты разработчика, на рабочем сайте не нужны |
| 2 | Better Search Replace, WP Mail SMTP, Contact Form 7, 301 Redirects | Минорные, риск низкий. После CF7 отправить тестовую заявку, после WP Mail SMTP — тестовое письмо |
| 3 | WP Fastest Cache | После обновления очистить кеш |
| 4 | Yoast SEO 26.5 → 28.5 | Может запустить фоновую переиндексацию; на 3500 товарах делать в спокойное время |
| 5 | Cyr-To-Lat 6.6 → 7.1 | Мажорная версия. Проверить требования к PHP. **Не запускать** конвертацию существующих ярлыков — сменятся URL |
| 6 | Duplicator 1.5 → 5.x | После того, как сделан бэкап |
| 7 | WooCommerce | Только если в статусе системы нет устаревших шаблонов, иначе сначала обновить их в теме. После обновления может понадобиться обновление БД WooCommerce — запустить его |
| 8 | ACF PRO 6.3.4 | Обновляется только с лицензионным ключом. Нужен ключ от заказчика или ставить новую версию zip-архивом с сайта ACF |
| 9 | Ядро WordPress → 7.1.2 | Последним. Только при наличии бэкапа и, желательно, доступа к хостингу |

Если плагин с wordpress.org сломал сайт после обновления, его можно откатить плагином **WP Rollback**. Для ACF PRO нужно заранее сохранить zip текущей версии.

## 3. Салон удалён → товары тоже (`mu-plugins/rs-salon-products.php`)

- Салон в корзину → его товары в корзину. Салон восстановлен → вернулись только эти товары, с прежним статусом.
  Корзина очищена → товары удаляются навсегда (вместе с вариациями, картинки в медиатеке остаются).
- Товар, привязанный ещё к другому салону, не трогается.
- Если товаров больше 50, работа идёт в фоне через Action Scheduler: *WooCommerce → Статус → Запланированные действия*, группа `rs-salon-products`.

**Перед установкой** уточнить в коде темы или в ACF два значения и при необходимости поменять константы в начале файла:

- `RS_SALON_POST_TYPE` — slug типа «Салоны» (виден в адресе: `edit.php?post_type=…`);
- `RS_SALON_META_KEY` — имя поля ACF у товара, где выбран салон (*ACF → Группы полей →* группа товара → колонка «Имя»).

После установки в списке салонов появится колонка **«Товаров»**.
Если там реальные цифры, связь найдена правильно. Если нули — константы указаны неверно (удалять салоны пока нельзя).
Проверку делать на салоне-черновике или сразу восстанавливать салон из корзины.

## 4. Спам (`mu-plugins/rs-antispam.php` + настройки)

Плагин:
- комментарии открыты только у товаров (отзывы), у остальных типов записей закрыты; пингбеки и трекбеки отключены;
- в форму добавлены скрытая ловушка и подписанная метка времени. Боты, которые отправляют POST сразу в `wp-comments-post.php`,
  и слишком быстрые отправки отсекаются;
- отзывы со ссылками или без кириллицы попадают в «Спам»;
- спам старше 14 дней удаляется автоматически.

После установки оставить тестовый отзыв без авторизации. Если он дошёл до «Ожидают проверки», можно поставить `RS_ANTISPAM_STRICT = true`:
тогда запросы без токена даже не записываются в базу.

Настройки (**Настройки → Обсуждение**):
- снять «Разрешить оповещения с других блогов»;
- включить «Комментарий должен быть одобрен вручную»;
- «Автоматически закрывать обсуждение для записей старше N дней», если нужно.

**WooCommerce → Настройки → Товары:** «Отзывы могут оставлять только подтверждённые покупатели» — радикальный,
но самый надёжный вариант, если отзывы к товарам не нужны от всех подряд.

Накопившийся спам удалить через *Комментарии → Спам → «Очистить спам»*.
